The five encoding classes

Everything hinges on whether the exponent field is all-zeros, all-ones, or in between. This is the table to reproduce from memory.

ClassE fieldM fieldValueExample (fp32)
Zero0x000±0 — sign is preserved0x00000000, 0x80000000
Subnormal0x00≠ 0(-1)S × 2-126 × 0.M — no implicit 10x00000001 = 2-149
Normal0x01–0xFEany(-1)S × 2E-127 × 1.M0x3F800000 = 1.0

The subnormal case is where most RTL bugs live. Exponent field 0x00 means the effective exponent is -126, not -127, and the hidden bit is 0 instead of 1. Two special-cases in one, and the naive E - 127 formula gets both wrong.

Two of these bite hardest in a scoreboard. NaN ≠ NaN means you cannot compare results with == — compare bit patterns with !== and special-case NaN. +0 == -0 means the reverse: a numeric compare will pass when the DUT returned the wrong zero sign, so bit-compare that case too.
Rounding

Five modes and the GRS bits

ModeAbbrevBehavior
Nearest, ties to evenRNEIEEE default. Ties go to the even mantissa LSB
Toward zeroRTZtruncate. Overflow returns max finite, not ∞
Toward +∞RUPceiling
Toward -∞RDNfloor. Makes x - x return -0
Nearest, ties awayRMMadded in 754-2008

Correct rounding needs three extra bits below the mantissa LSB:

  • Guard — first bit shifted out
  • Round — second bit shifted out
  • Sticky — OR of every bit beyond that

Sticky is the one implementations get wrong, because it must be an OR accumulated over an arbitrarily long shift, not just the next bit. If the alignment shift exceeds the mantissa width, every shifted-out bit collapses into sticky and the guard/round bits are zero.

Addition

1.5 + 2.25 = 3.75

// unpack 1.5 = 0x3FC00000 S=0 E=127 (2^0) M=100...0 -> 1.1000₂ x 2^0 2.25 = 0x40100000 S=0 E=128 (2^1) M=001 0...0 -> 1.0010₂ x 2^1 // 1. align to the LARGER exponent: shift 1.5 right by 1 0.1100₂ x 2^1 + 1.0010₂ x 2^1 = 1.1110₂ x 2^1 // 2. normalize: already in [1,2), no shift needed // 3. round: G=R=S=0, exact // 4. pack result S=0 E=128 M=111 0...0 -> 0x40700000 = 3.75

The five steps, in order

  • Unpack — extract S/E/M, insert the hidden bit (1 for normals, 0 for subnormals)
  • Align — right-shift the smaller operand by the exponent difference, accumulating sticky
  • Add or subtract — effective operation is S_a ^ S_b, not the opcode
  • Normalize — leading-zero count then left-shift, or right-shift by 1 on carry-out
  • Round and pack — apply GRS, re-normalize if rounding carries out of the MSB

1.0 + 2-24 = 1.0 — the tie case

1.0 = 1.000...0₂ x 2^0 ulp = 2^-23 2^-24 = 1.000...0₂ x 2^-24 exactly HALF an ulp // align: shift right by 24 -> falls entirely below the LSB 1.00000000000000000000000 | G=1 R=0 S=0 // exact tie. RNE breaks it toward the EVEN mantissa. // current LSB = 0 (already even) -> round down result = 0x3F800000 = 1.0 flags: NX (inexact)

Change one thing and the answer changes: (1 + 2⁻²³) + 2⁻²⁴ is the same tie, but the LSB is now 1 (odd), so RNE rounds up to 1 + 2⁻²². A DUT that always rounds ties up passes the first test and fails the second.

Alignment beyond the mantissa width

1.0 + 2^-150 // exponent difference = 150 > 24 bits of precision // the entire operand collapses into sticky 1.00000000000000000000000 | G=0 R=0 S=1 result = 1.0 flags: NX

Clamp the shift amount. A barrel shifter fed a raw difference of 150 into a 24-bit datapath will wrap or produce zero sticky, and the inexact flag is lost.

Multiplication

1.5 × 2.25 = 3.375

// multiplication is easier: no alignment step sign = S_a XOR S_b = 0 ^ 0 = 0 exponent = E_a + E_b - bias = 127 + 128 - 127 = 128 mantissa = 1.1000₂ x 1.0010₂ = 1.1011₂ (= 1.6875) // product of two values in [1,2) lands in [1,4) // here it is < 2, so no normalization shift result = 1.6875 x 2^1 = 3.375 -> 0x40580000

Where multiplication differs

  • Exponent is a sum, so the bias is subtracted once. Overflow and underflow are detected on that sum, before rounding.
  • The product is 2×precision wide — 48 bits for fp32. All 48 feed the sticky computation.
  • Normalization is at most one bit. Two normals in [1,2) give a product in [1,4), so a single right-shift covers it. Subnormal inputs break that guarantee and need a full leading-zero count.

Overflow and underflow

// overflow: 2^100 x 2^100 exponent = 227 + 227 - 127 = 327 > 254 (max) RNE / RUP -> +Inf 0x7F800000 flags: OF, NX RTZ / RDN -> max finite 0x7F7FFFFF flags: OF, NX // underflow to subnormal: 2^-100 x 2^-30 exponent = 27 + 97 - 127 = -3 < 1 (min normal) -> gradual underflow, encoded as subnormal, precision lost flags: UF, NX // underflow to zero: 2^-149 x 2^-149 -> +0 flags: UF, NX
Overflow behavior depends on the rounding mode. RTZ and RDN return the largest finite value rather than infinity. A DUT hardwired to return ∞ on overflow is wrong in two of the five modes.
Reference model

Get the golden model right first

Do not hand-write expected values. Use a trusted model and compare bit patterns.

// SV native: shortreal is binary32, real is binary64 bit [31:0] a_bits, b_bits, dut_out, exp_bits; shortreal a, b, r; a = $bitstoshortreal(a_bits); b = $bitstoshortreal(b_bits); r = a + b; exp_bits = $shortrealtobits(r); // bit compare, NOT numeric compare if (exp_bits !== dut_out) `uvm_error("FP", "mismatch")
The host FPU only implements RNE and gives you no access to the exception flags. For the other four rounding modes and for flag checking, bind Berkeley SoftFloat through DPI-C — it is the reference the RISC-V FP tests use, it exposes softfloat_roundingMode and softfloat_exceptionFlags, and it handles subnormals correctly.

Exhaustive

Prove it on binary16 first

The strongest argument you can make in a review. If the RTL is parameterized by exponent and mantissa width, elaborate it as binary16 and sweep the entire space.

ScopeCountFeasible?
fp16 unary (sqrt, convert, class)65,536seconds
fp16 binary, all pairs4.3e9overnight in C, sampled in SV
fp16 binary × 5 rounding modes2.1e10C reference only
fp32 binary, all pairs3.4e19never — constrained random

An exhaustive fp16 pass finds essentially every structural bug — sticky logic, subnormal handling, tie-breaking, flag generation. What it will not find is anything that depends on the wider datapath, so it complements rather than replaces fp32 random.

Constrained random

Bias toward the boundaries

typedef enum { ZERO, SUBNORM, SMALL, NORMAL, LARGE, INF, QNAN, SNAN } fp_class_e; rand fp_class_e cls_a, cls_b; rand bit [31:0] a, b; rand bit [2:0] rm; // specials are rare in a uniform 32-bit draw -- force them constraint c_cls { cls_a dist { NORMAL := 40, SUBNORM := 15, ZERO := 10, SMALL := 10, LARGE := 10, INF := 5, QNAN := 5, SNAN := 5 }; } // near-cancellation: exponents within 2 of each other, opposite signs constraint c_cancel { solve cls_a before a; if (near_cancel) { a[30:23] - b[30:23] inside {[-2:2]}; a[31] != b[31]; } }

A uniform random 32-bit value is a normal number essentially every time — infinities and NaNs are 2-8 of the space and subnormals less than that. Without class-directed constraints, a million random vectors will never test the paths that actually break.

Coverage model

  • Input class cross — cls_a × cls_b, all 64 bins, crossed with rounding mode
  • Result class — did the DUT ever produce a subnormal, an infinity, a NaN, a signed zero?
  • Flag cross — each of NV/DZ/OF/UF/NX raised, and the combinations that co-occur (OF always implies NX)
  • GRS bins — all 8 combinations of guard/round/sticky at the rounding point
  • Tie cases — exact ties with LSB even and LSB odd, separately
  • Alignment shift — bins at 0, 1, 23, 24, 25, and > 25 (the clamp boundary)
  • Normalization shift — leading-zero count of 0, 1, mid-range, and maximum (full cancellation)
Assertions

Properties worth binding

// any NaN input must produce a NaN output a_nan_prop: assert property (@(posedge clk) disable iff (!rst_n) (valid_in && (is_nan(a) || is_nan(b))) |-> ##LAT (valid_out && is_nan(result))); // the DUT must never emit a signaling NaN a_no_snan_out: assert property (@(posedge clk) disable iff (!rst_n) valid_out |-> !is_snan(result)); // exponent field all-ones implies mantissa is either 0 (Inf) or a NaN a_legal_enc: assert property (@(posedge clk) disable iff (!rst_n) valid_out |-> !$isunknown(result)); // overflow always co-occurs with inexact a_of_implies_nx: assert property (@(posedge clk) disable iff (!rst_n) (valid_out && flag_of) |-> flag_nx); // commutativity of add and mul -- run the same pair both ways // (holds bit-exactly in IEEE 754, including NaN payload rules)

Scoreboard gotchas

  • Never compare with == on real values. NaN ≠ NaN, so every NaN test would silently pass. Compare the 32-bit patterns with !==.
  • Bit-compare catches the zero-sign bug that numeric compare misses. +0 == -0 is true numerically but the encodings differ, and the sign of zero is specified.
  • NaN payload propagation is implementation-defined in 754 but usually pinned by your ISA spec. RISC-V, for instance, requires the canonical qNaN 0x7FC00000 for every NaN-producing operation, so a DUT that forwards the input payload is wrong for that ISA. Check the spec before writing the check.
  • Underflow flag timing. 754 permits detecting tininess before or after rounding. The two differ on a narrow band of results. Pick one, document it, and make the reference model match.
  • Flush-to-zero mode, if the DUT has one, changes subnormal expectations entirely. Verify both modes, and verify the mode bit itself controls the behavior.
